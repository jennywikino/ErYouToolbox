# OB6-C1 紧凑列表

## 改动

- 本地列表工具栏新增标准/紧凑切换、每页 15/25/50 件。默认紧凑、25 件。
- 密度和页大小保存在浏览器 `localStorage.eryouListing`，只作为界面偏好，不保存作品状态。
- 最新、订阅、作者页复用同一列表；热门榜使用独立在线分页组件，本轮保持原有 20 条与标准卡片，不修改算法。
- React 本地 `/api/mods` 的 limit 上限由 20 改为 50；默认 API limit 18 为兼容旧调用保留，网页始终明确传入用户选择的数量。查询继续使用原参数化筛选及 LIMIT/OFFSET。
- 紧凑卡片为约 4:3 图片、两行标题（title 悬停显示完整文字）、作者、游戏和已阅操作。原站链接、日期、评级详情与更新说明保留在详情页；标准卡片仍显示原信息。
- 紧凑网格桌面 5/4 列，窄窗口继续减少。宽屏内容最大 1240px，使卡片高度维持约 230～270px；小窗口、错误提示及额外状态可能增加高度。
- 复用现有缩略图地址、IntersectionObserver、懒加载与重试。优先已有卡片缩略图，其次小图；旧字符串数组继续可读，不拼造 URL，不改变详情高清图策略。
- 网格实际列数用于首排加载优先级；密度切换不会请求列表或发起 GameBanana 同步。
- 页大小切换按原第一页偏移换算到新页，尽量使原首条仍在新页内，并用作品身份恢复位置；数据变化造成越界时沿用服务端总数进行页码收敛。筛选保持不变。
- 返回位置快照增加 pageSize/viewMode，兼容旧 18 条分页快照。旧快照没有页大小时按原偏移近似换算；找不到锚点时保留原像素回退。

## 本机验收

需要重启现有 API 和前端：旧 API 进程仍执行旧的 20 条上限，仅刷新网页不足以更新后端。使用原关闭/启动器，不结束其他项目的进程。

1. 最新列表确认默认紧凑/25；切换标准，检查原信息仍存在。
2. 分别选择 15/25/50，翻到末页，确认无 limit 错误、页码不越界。
3. 保持游戏、搜索、评级和已阅条件，切换每页数量；检查原首条仍位于新页范围内。
4. 第三页中部打开详情后返回，检查模式、数量、条件与位置；浏览器后退/前进也应恢复快照。
5. 刷新网页检查偏好保留，分别访问订阅和作者页。
6. 检查无图占位、已阅操作与高清详情画廊；Network 的列表图片应为已保存缩略图，而非一次性请求整套画廊原图。
