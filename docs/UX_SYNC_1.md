### 使用与数据流

- 本地列表查询独立进行，不等待网络同步；App挂载后先GET本地状态确认服务就绪，再POST `/api/auto-sync/startup`。
- 前端单文档Promise去重；后端AutoSync实例另以锁保护 `browser_startup_done`。同一服务只自动发起一次，切换六游戏、分区、详情、重载页面和同服务多标签页均不能再次自动扫描。服务重启后内存标记重置，允许新的一轮。
- 移除App一分钟到期计时器及requestDueCheck，不再按三小时间隔触发。SyncCheck仍每1.5秒只读轮询进度，这不请求GameBanana、不启动任务。
- 启动和紫色“刷新MOD”均走既有AutoSync工作线程、六游戏串行WebSync及 `apply(only_source_changes=True)`，无需常规确认。刷新提交空对象表示六游戏，不随当前浏览游戏缩小范围。
- 本次新规则覆盖原浏览器off/check/apply控制。旧设置文件不覆盖、不删除，但旧mode不阻止本次启动/手动一次性入库；写入前仍检查停止信号和扫描期间设置是否改变。CLI及已有Windows计划任务兼容入口仍保留，未注册、禁用或修改任何真实系统任务；它们不属于客户端新增调度。若旧电脑已有外部计划任务，需用户单独查询/管理，不能声称本轮关闭了系统任务。
- 关闭后重新打开客户端（本地服务重新建立）可再次检查，无需等三小时；只重载网页、仍复用同一服务则不会再自动检查。冷却不会因重启而绕过。

### 查询与预览

工具栏仅保留紫色“刷新MOD”、简短启动说明、更多设置、缓存管理及运行时停止。移除独立“手动导入 MOD”、提示描边及常规“待确认导入”按钮。

精确链接/ID功能位于搜索框旁的“高级查询”，保留来源游戏选择、官方链接/ID解析、身份验证、预览、确认保存和放弃。该对话框独立于当前列表分区及详情显示，切换页面不会因父容器hidden而打不开。未选游戏时明确要求选择，不猜游戏。

已有旧预览不会自动覆盖/确认：主栏只显示文字提示，精确查询在高级查询处理，旧同步预览在更多设置处理。这属于安全恢复边界，正常启动同步成功后不产生人工确认步骤。来源/身份/预览过期冲突仍会安全拒绝。

### 预算与数据保护

空库启动每游戏最多1页，每页10条；已有库和手动刷新每游戏最多3页（旧配置更小时遵守更小值）。沿用90天窗口、重叠复核、有限重试、来源更新时间证据；不启动大规模历史补全，不宣称全站覆盖。每页采集最多2次尝试（含失败重试），上限为六游戏6/18页、12/36次列表尝试；已有作者轮转仍采用其独立有限预算。

复用实例锁/共享写锁、备份、事务及回滚；不重建数据库，不清除已阅、关注、笔记、历史、图片及同步游标。全部失败保留旧数据；一游戏失败保留其他游戏有效结果。重复刷新有运行锁及短时去重；429/403仍遵守持久冷却。一次启动失败不循环重试，用户可点击刷新MOD重试。已有待处理预览或冷却时，本次启动尝试安全停止，不承诺必定取得作品。

## 数据流及实际复用

启动：App加载本地列表，与其独立调用autoStartup → `/api/auto-sync/startup` → `AutoSync.browser_launch(startup=True)` → 现有launch/run工作线程。

未配置时在原settings.lock保护下保存默认apply；**不会覆盖已有off或check**。这项默认行为由UX-SYNC-1需求取代早期“新用户先手动授权保存模式”的流程。命令行AutoSync默认off保持不变，CLI不会凭空开启。

到期检查：现有App每分钟提交到期提示，服务端再次核对3小时间隔、429/403冷却、共享锁、待确认预览和设置。周期检查不是全库重建。已有自定义间隔保留，不强制重置为3小时。客户端关闭后不新增后台服务或计划任务。

手动刷新：`/api/auto-sync/refresh` → 同一个AutoSync工作线程 → `WebSync.check_games` → normalize/既有importer比较 → `WebSync.apply(only_source_changes=True)`。本次操作允许在已保存off/check时一次性入库，后台偏好不变。若扫描期间偏好改变或收到停止信号，写入前guard拒绝提交。

手动导入：`/api/sync`的lookup → `WebSync.lookup`/SourceDetail → 持久预览及token → 用户确认 → 既有WebSync.apply。既有无变化/身份不匹配/预览过期/数据库变化/限流检查继续有效。已存在MOD不重复插入。手动导入不推进六游戏扫描游标。

`/api/sync`轮询提供当前游戏、页数及完成数；`/api/auto-sync`提供实际入库结果，完成后现有onComplete刷新列表，沿用筛选和浏览锚点恢复，不强制刷新整个网页。运行中不展示确认按钮，防止把正常自动流程当成必须人工处理。

## 范围与安全

- 新用户空库初始：六游戏串行，每游戏最多1页、每页10条候选；最多60条来源候选，并非保证收录60条或全站覆盖。
- 已有库：默认每游戏最多3页；仍用90天发布/可靠更新时间/来源修改时间的有界发现规则、重叠检查和独立已提交检查点。每页采集器请求预算2（含重试），沿用超时和1秒页间间隔；六游戏最多18页、36次列表尝试。已有作者轮转另有自己的有限预算，不新增扫描器。
- 模式明确保存为off时，启动和周期任务不联网；明确check时不自动写MOD。主“刷新”是用户主动的一次性入库操作。
- AutoSync进程内running锁与原共享instance.lock防并发；两秒内重复手动请求抑制，不绕过冷却。后台任务不受浏览器连接关闭影响，关闭客户端仍沿用既有安全退出流程。
- 使用现有SQLite Online Backup、事务、来源身份及来源更新证据校验；只自动导入新作品和可靠来源更新。纯资料补全不冒充作者更新。
- 保留已阅、关注、笔记、高清图、评级原始证据、历史与userdata；不重建数据库、不改变schema、不下载MOD文件。
- 手动预览不会被自动任务覆盖。遇到待处理预览仍需确认或放弃，这是有意保留的数据安全边界。
- 离线时不删除旧数据或错误推进游标。此次修正了全游戏检查失败后作者分支可能把结果改成partial的问题：全部MOD检查失败时保留failed并跳过该次作者检查。
- 手动导入的一次提示仅轻微描边，8秒或点击后结束，无持续动画。仅观察到首次未配置状态时尝试显示；不会为了显示提示延迟首屏或同步。
