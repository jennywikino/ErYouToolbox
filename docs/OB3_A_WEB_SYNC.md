# 网页同步 MVP 验收

最新 MOD 顶部选择具体游戏后点击“检查新 MOD”。全部游戏不允许检查。
复用 collect_game，以 Generic_NewAndUpdated 取一页最多 20 条；临时失败沿用一次重试，429 沿用既有限流处理。覆盖始终 incomplete。

GET /api/sync 查询当前进程任务状态；POST /api/sync 只接受 check/game 或 confirm/game/token。
POST 沿用 Host、Origin、JSON Content-Type 与 X-ErYouToolbox 请求保护，服务器仍绑定 127.0.0.1。
网络在工作线程中顺序执行，页面轮询；复用内容分级回填的 OS 文件锁，导入由 SQLite BEGIN IMMEDIATE 串行化。
预览候选不由浏览器提交，服务器保留十分钟。确认时在写锁内校验 mods 全表指纹，任何作品变化都会拒绝旧预览；人工已阅变化不应使预览失效，也不会被导入覆盖。
已有图片与 content_rating_status 原样保留，来源分级证据由现有 importer 保护。新增作品使用采集器标准化数据。
实际变化触发现有 Backup API，备份失败或事件写入失败全部回滚，sync_runs 和作品事件同事务提交。

## 本机步骤

1. 通过现有 stop_toolbox.cmd / start_toolbox.cmd 重启 API 和前端；不应结束其他手动启动的服务。
2. 最新 MOD 选择原神，点击检查。应显示扫描数、来源更新数和失败原因，数据库此时不变。
3. 关闭网页再打开，任务状态仍可查询（限同一个 API 进程）。API 重启会丢弃内存预览，必须重新检查，不能直接确认旧 token。
4. 核对统计后由用户手动点击确认导入；观察备份、成功或部分成功状态，列表自动刷新。
5. 再次检查、确认，不应重复新增身份或事件；已阅、关注、已有高清图片与来源分级应保留。
6. 检查期间连续点击不应创建第二个任务。切换游戏后不能确认另一个游戏的预览。

## 本轮测试边界

临时 SQLite + 模拟来源测试覆盖预览/确认 HTTP 流程、持久化、幂等、来源更新时间、冲突、过期、备份失败及事件事务失败。
超时与 429 使用采集器返回的失败报告测试；客户端 HTTP 行为另由既有采集测试负责。
真实原神预览：一次请求、20 条、预计新增18、元数据更新2、来源更新事件1、无失败；生产库仍797条。没有执行生产确认。
没有进行真实浏览器点击验收；生产写入须由用户按上述步骤手动确认。
